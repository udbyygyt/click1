# Click+1 实施计划

## Phase 1：规则引擎

### Task 1：棋盘和点击

- 实现 6×6 棋盘、点击加一、行动力和游戏状态。
- 验收：点击非法状态不会改变棋盘；行动力为 0 时禁止点击。
- 分数采用每个合并区域“合并前输入数字总和”，不设连锁倍率。

### Task 2：合并和连锁

- 实现正交连通区域、锚点选择、批量合并和连锁扫描。
- 验收：三连、多连、多区域和连锁结果稳定可重放。

### Task 3：下落和生成

- 实现列向下压缩、顶部生成、概率表和满盘结束。
- 验收：固定 seed 下生成序列一致；列内顺序不改变。

### Checkpoint 1

- 规则单元测试全部通过。
- 客户端和服务端共享引擎得到相同结果。

## Phase 2：撤回和账户

### Task 4：单步快照撤回

- 保存每次点击前快照。
- 撤回后锁定撤回能力，下一次点击后重新开放。
- 验收：不存在连续撤回；撤回恢复随机状态和新生成方块。

### Task 5：钱包登录

- 接入 MWA 和 SIWS。
- 实现会话恢复和钱包断开。
- 验收：Seed Vault、Phantom、Solflare 至少各通过一次。

### Task 6：每日免费次数

- 服务端按 UTC+0 生成每日权益。
- 验收：UTC 00:00 切换，不累计，不受设备时区影响。

### Task 6a：当前局唯一性

- 以钱包地址约束只能存在一局活动游戏；开始新局前归档旧局。
- 验收：并发创建请求只成功一个；旧局不能恢复为活动局。

### Checkpoint 2

- 钱包登录后可开始游戏。
- 每日免费撤回在客户端和服务端状态一致。

## Phase 3：付费撤回

### Task 7：支付订单

- 创建 0.01 SOL 订单并绑定 wallet、game、move。
- 验收：重复创建和重复确认均幂等。

### Task 8：链上交易验证

- 校验付款人、收款人、金额、网络、Memo 和成功状态。
- 验收：取消、失败、误付、重复签名、断线恢复均有明确结果。
- 生产只允许 mainnet-beta；devnet 配置不能打进生产 APK。
- 付款前无网络时不得执行撤回；所有撤回都要求联网确认。

### Checkpoint 3

- 测试网完成全流程。
- 主网上线前完成政策和收款地址复核。

## Phase 4：体验和发布

### Task 9：多语言

- 完成 en、zh-CN、ja 语言包和设置页。
- 验收：英文默认，语言切换立即生效，无缺失 key。

### Task 10：动画音效

- 实现点击、合并、下落、生成、撤回、结束和通关效果。
- 使用程序合成音效或有明确授权的素材。

### Task 11：APK 和商店材料

- 生成独立签名 APK。
- 准备图标、截图、描述、隐私政策、服务条款和客服入口。
- 验收：APK 可安装，商店文案不包含收益、下注或投资承诺。
- 商店材料明确：0.01 SOL 是一次性游戏功能费用，正常链上支付不可撤销；同时提供适用法律声明和异常支付客服渠道。

### Checkpoint 4

- Android/Seeker 测试通过。
- 发布前完成个人发布者 KYC/KYB、钱包和密钥备份。
- 提交 Publisher Portal 审核。
