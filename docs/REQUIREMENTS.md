# Click+1 for Solana Seeker 需求文档

## 1. 文档信息

- 版本：v1.0
- 状态：需求定稿草案，进入实现前评审
- 平台：Solana Seeker / Android，首选 dApp Store
- 默认语言：English
- 支持语言：English、简体中文、日本語
- 时区基准：UTC+0
- 生产网络：Solana mainnet-beta
- 开发/测试网络：Solana devnet，仅限非生产环境
- 服务端框架：Node.js + TypeScript + Fastify 5

## 2. 用户和目标

### 目标用户

拥有 Solana 钱包、希望在 Seeker 上进行短时益智游戏的用户。

### 产品目标

- 3 秒内让用户理解“点击数字使其 +1”。
- 单手完成一局 2～5 分钟的游戏。
- 撤回行为可预测、可验证，不出现连续撤回歧义。
- 钱包支付流程透明，不把游戏包装成投资或博彩产品。
- 个人开发者可以独立维护和发布。

## 3. 账户和首次进入

### 必须连接钱包

- 禁止游客模式。
- 未连接钱包时只能看到产品介绍、玩法说明和设置，不能开始游戏。
- 支持 MWA 钱包：Seed Vault、Phantom、Solflare 等。
- 使用 SIWS 完成登录，签名成功后建立应用会话。
- 应用不得索要助记词或私钥。

### 当前局唯一性

- 每个钱包地址最多保留一局当前游戏。
- 开始新局必须二次确认；确认后旧局标记为 `abandoned`，不再作为当前局恢复。
- 卸载、重装或换设备后，钱包重新授权即可恢复该钱包唯一的当前局。
- 服务端以钱包地址约束并发创建，客户端不得自行覆盖活动局。

### 钱包断开

- 用户主动断开后，停止新局和新操作提交。
- 已缓存的当前局只允许在重新授权后继续。
- 断开钱包不会删除云端数据。

## 4. 游戏规则

### 棋盘

- 棋盘为 6×6。
- 行号从上到下，列号从左到右。
- 只认上下左右，不认对角线。
- 初始棋盘由固定随机种子生成。

### 点击

- 点击一个方块，数字 `N` 变成 `N+1`。
- 每次点击消耗 1 点行动力。
- 点击后先处理所有合并，再处理下落和新方块生成。
- 一次点击最多生成一个新方块。

### 合并

- 三个或更多相同数字、正交连通的方块组成一个合并区域。
- 合并区域全部变为一个数字加 1 的方块。
- 玩家点击触发的首轮合并，锚点为点击方块；自动/连锁合并先取区域最下面一行，再取该行最左侧的方块作为锚点。
- 多个合并区域按“下到上、右到左”确定处理顺序。
- 同一轮先确定全部区域，再批量合并，避免遍历顺序导致结果不同。
- 合并完成后执行下落，并继续扫描连锁合并。
- 连锁完全结束后才生成新方块。

### 下落

- 重力方向固定向下。
- 每列独立压缩，空位移动到该列顶部。
- 方块在列内保持原有上下顺序。
- 不支持左右移动、旋转或玩家手动选择下落方向。

### 新方块

- 从棋盘上方进入。
- 在仍有空位的列中随机选一列。
- 方块落到该列最底部空位。
- 生成数字按生成前的最高数字 `H` 决定：

| H | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| H < 8 | 60% | 30% | 10% | 0% | 0% |
| 8 ≤ H < 14 | 50% | 30% | 15% | 5% | 0% |
| H ≥ 14 | 45% | 30% | 15% | 8% | 2% |

- 新生成数字不超过 5。
- 所有列都没有空位且本次点击没有释放空位时，游戏结束。

### 行动力

- 初始行动力：5。
- 上限：5。
- 每次点击：-1。
- 每发生一轮合并：+1。
- 连锁合并两轮则返还 2 点，最终不超过上限。
- 行动力为 0 时不能点击，但仍可撤回。

### 分数和通关

- 首版必须显示分数和最高数字。
- 分数采用“合并输入数字总和”公式：每个合并区域将被合并的所有方块数字按合并前数值相加，所得总和直接加入分数，不使用额外倍率。
- 例如 `3+3+3→4` 得 9 分；`4+4+4+4→5` 得 16 分；一次点击触发两轮连锁则分别计算并相加。
- 点击但没有发生合并不加分；下落和新方块生成不加分；撤回恢复点击前分数。
- 同一轮多个合并区域分别计分，总分与遍历顺序无关。
- 达到数字 20 显示通关状态，但允许继续游戏。
- 首版不做公共排行榜和排名奖励。

## 5. 撤回需求

### 单步限制

- 每次操作只能撤回一步。
- 一步包含该次点击、所有连锁合并、下落和新方块生成。
- 撤回恢复棋盘、分数、行动力、随机状态和游戏状态。
- 撤回后立即禁止再次撤回。
- 必须进行一次新的点击后才能再次撤回。
- 同一局不限制累计撤回次数。
- 撤回后新点击会形成新的历史分支，不提供 redo。

### 免费撤回

- 每个钱包按 UTC+0 每日获得 1 次免费撤回。
- 每日切换时间为 UTC 00:00:00。
- 免费次数不累计。
- 免费次数可用于任意一局。
- 免费次数由服务器最终判断，客户端缓存只用于展示。

### 付费撤回

- 免费次数为 0 且存在可撤回步骤时，撤回价格为 0.01 SOL。
- 金额固定为 10,000,000 lamports。
- 网络费由用户另行承担。
- 每次付费撤回需要用户主动确认并签名。
- 同一局可以无限次付费撤回，但必须每次先有新点击。
- 付款成功前不得改变游戏状态。
- 交易确认后才能执行撤回。
- 正常链上支付原则上不可撤销；应用条款可以声明付费撤回不退款，但必须保留适用法律要求的消费者权利以及重复扣款、服务故障或错误支付的处理渠道。

### 收款地址与发布钱包

- Publisher Wallet 用于 Publisher Portal、App NFT/Release NFT 和发布交易。
- Undo Treasury Address 用于接收 0.01 SOL 撤回费用。
- 两者默认分离，分别由环境变量配置并在管理文档中登记；公开提交流程要求发布钱包，但没有公开规定应用内收款地址必须相同。
- 如果个人开发者选择共用地址，必须记录发布密钥泄露将同时影响运营收款资金的风险。

### 失败场景

- 用户取消钱包：保持原棋盘，不扣除次数。
- 交易失败：保持原棋盘，订单标记失败。
- 金额错误：不执行撤回，进入人工/客服处理流程。
- 交易成功但客户端断线：重新进入后查询订单并恢复结果。
- 重复点击确认：同一订单只允许执行一次。

## 6. 多语言和界面

### 语言

- 默认语言固定为 English，不跟随系统语言自动切换。
- 设置中可切换：English、简体中文、日本語。
- 切换立即生效并持久化到本地。
- 所有用户可见文案必须来自语言包，不允许逻辑中写死。
- 语言包缺失 key 时回退到 English，并记录开发日志。

### 必须翻译的内容

- 钱包连接、签名和断开提示。
- 游戏规则、行动力、分数、通关和结束状态。
- 撤回按钮、免费次数、0.01 SOL 确认框。
- 网络错误、交易状态、客服和隐私政策入口。
- 设置、音效、震动和语言页面。

### 页面

- Welcome / Connect Wallet。
- How to Play。
- Game。
- Undo confirmation。
- Settings。
- Transaction status。
- Privacy Policy / Terms / Support。

## 7. 动画、音效和触感

### 动画

- 点击：缩放 1.00 → 1.12 → 1.00，约 160ms。
- 合并：方块移动到锚点、非锚点消失、锚点放大和粒子爆发。
- 下落：每格约 70～90ms，落地轻微压缩和反弹。
- 生成：从顶部落入，约 180～220ms。
- 撤回：当前状态淡出，恢复快照，约 220ms。
- 动画期间输入必须排队或锁定，不能造成重复操作。

### 音效

- 首版优先使用 Web Audio/Tone.js 程序合成短音效。
- 点击、普通合并、连锁合并、高数字合并、生成、撤回、结束和通关分别有独立音效事件。
- 采用五声音阶，避免连续点击刺耳。
- 支持关闭音效和震动。
- 若使用外部或 AI 生成素材，必须确认商业授权并记录来源。

## 8. 网络和离线需求

- 生产版本固定使用 Solana mainnet-beta。
- devnet 只允许开发、QA 和内部演示配置，不能被生产 APK 选择。
- 已登录用户可以在短时断网时继续当前局的本地点击。
- 撤回功能必须联网：免费和付费撤回都必须先访问服务端确认权益/订单，再改变游戏状态。
- 无网络时撤回按钮显示不可用；不得先本地撤回再异步扣款。
- 付费交易确认和每日免费次数以服务器结果为准。

## 9. 非功能需求

- 目标设备：Seeker；同时兼容常见 Android 模拟器和 Android Chrome。
- 目标渲染：稳定 60 FPS，充分利用高刷新率但不能依赖 120Hz。
- 新局需要完成钱包授权；已授权当前局可在短时断网下继续本地操作。
- 无网络时不能发起任何撤回，恢复网络后可查询或重试订单。
- 所有关键服务接口必须有超时、重试和幂等策略。
- 首版不要求 Redis；使用 PostgreSQL 唯一索引、事务和行锁实现当前局、每日权益和订单幂等。
- 生产 API 部署在开发者自有的腾讯云新加坡轻量服务器上，通过 Caddy 提供 HTTPS；PostgreSQL 与 API 使用 Docker Compose 运行，数据库不暴露公网端口。开发和测试可使用同一服务器的隔离环境，但生产必须固定 mainnet-beta。
- 服务器运维由开发者负责：系统补丁、Docker 更新、TLS、数据库备份、磁盘监控、日志轮转和故障恢复。
- 不采集产品分析、行为追踪或广告标识；仅保留安全、支付、错误排查所需的技术日志，且不得记录私钥、助记词或完整签名消息中的敏感数据。
- 提供账户删除和关联用户数据删除入口，依法需要保留的反欺诈/交易记录除外。
- 提供隐私政策、服务条款、客服邮箱和问题反馈入口。

## 10. 验收标准

### 规则

- 三连、四连、L 型、多区域和连锁合并结果符合规则。
- 下落始终向下，列内顺序不变。
- 生成数字符合概率表和随机种子重放结果。
- 满盘、合并释放空位和游戏结束边界均有测试。

### 撤回

- 撤回准确恢复最近一步的全部状态。
- 撤回后不能连续撤回。
- 新点击后可以再次撤回。
- 同一局连续进行多次“点击→撤回”不会触发人为上限。
- 免费次数按 UTC+0 正确切换且不累计。
- 付费交易成功、取消、失败、重复和断线恢复均通过测试。
- 无网络时免费/付费撤回均不可执行；联网后才能继续。
- 同一钱包创建第二局时旧局被明确归档，不能存在两局活动游戏。

### 国际化

- 首次进入显示英文。
- 中文和日语没有缺失或截断文案。
- 数字、SOL、时间和错误提示在三种语言下可读。

### 发布

- APK 使用独立 dApp Store 签名密钥。
- 商店描述没有下注、收益或投资承诺。
- 隐私政策、服务条款、客服入口可访问。

## 11. 已确认决策与仍需落实事项

以下事项原始需求尚未明确，已列为上线前决策点：

1. **分数公式（已确认）**：采用合并输入数字总和，不使用额外倍率。
2. **当前局（已确认）**：每个钱包只保留一局；新局归档旧局。
3. **收款地址（已确认方案）**：默认与 Publisher Wallet 分离；官方提交流程要求发布钱包，但未规定必须与应用内收款地址相同。若共用，需接受密钥和资金共担风险。
4. **退款（已确认原则）**：正常链上支付原则上不退款；条款不能排除适用法律的强制性权利，并保留重复扣款、故障和误付处理渠道。
5. **网络（已确认）**：生产 mainnet-beta；devnet 仅开发测试。
6. **参考案例（已落实）**：已参考 Seeker 上架游戏常见做法：钱包作为身份、云存档、MWA、触感/音效反馈，以及固定价格的链上数字功能支付；本项目不引入排行榜、下注或收益奖励。
7. **年龄和地区限制**：付费功能上线前仍需确认目标市场的虚拟资产、数字商品和未成年人规则。
8. **审核预沟通（建议执行）**：官方条款对 dApp Store/Application Fees 写明通常不可逆且 Solana Mobile 不承担退款义务，但这不等同于对本应用自有收款转账的预批准；应用开发者仍需遵守适用法律。提交前应把 0.01 SOL 撤回说明、非退款政策和异常处理方案提交到官方 `#dev-answers` 请求预审。
9. **数据采集（已确认）**：不采集产品分析、行为追踪或广告标识；只保留运行、支付和安全所需日志。
10. **离线策略（已确认）**：已登录用户可离线继续点击，但撤回必须联网；免费次数和付费结果以服务器为准。
